# 内容创作与运营 Agent：8 周每日开发任务 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在每周 15 小时的约束下，用 8 周交付支持多用户隔离、对话与定时生成、Tool、MCP 搜索、通知及数据复盘的第一版内容创作 Agent。

**Architecture:** 按单个 Spring Boot 后端与 Vue 前端规划；MySQL 保存业务状态，Redis + Redisson 提供会话/缓存及并发辅助。建议使用 LangChain4j 接入模型和工具、LangGraph4j 组织有界生成流程，第 1 周用真实接入验证组合。审阅通过已保存草稿和版本处理，不让后台线程一直等待用户操作。

**Tech Stack:** Vue 3、TypeScript、Java（建议 21）、Spring Boot 3、LangChain4j、LangGraph4j、DeepSeek、MySQL、Redis、Redisson、Docker Compose。持久层建议 Spring Data JPA + Flyway，认证建议 Spring Security + Redis 会话；这些是排期采用的实施默认值，具体兼容版本由 W1-D1/W1-D4/W1-D5 的接入验证固定。

整理日期：2026-09-24。需求依据：[项目需求与实施计划](../../项目需求与实施计划.md)。当前目录仅有简历与需求文档，尚无应用工程；下方代码文件均为计划创建的文件，命令用于工程建立后的验收，不表示当前已有这些功能。

本轮交付为日级任务计划。三个里程碑可分别验收；执行中每一天的任务进一步按小步骤完成，不要求一次实现整份计划。引用技能中的执行方式用于后续开发，本轮不启动编码或代理任务。

## Global Constraints

- 架构：前后端分离；前端：Vue 3 + TypeScript；后端：Java + Spring Boot 3。
- 数据库：MySQL；缓存及 Java 客户端：Redis + Redisson。
- 第一版包含本地 Tool 和 MCP Client；第一版不建设 MCP Server。
- 每个用户独立管理自己的多个内容账号；邀请注册；不引入团队共享。
- 首个账号尚未注册，无历史作品；Java 面试快问快答为主，托福英语跟读为辅。
- 每周频率：3 条：2 条 Java + 1 条英语。账号栏目和频率可配置。
- 选题卡片、完整脚本、内容排期三类交付物均属于第一版。
- 对话可逐步确认或直接生成；定时任务生成草稿，不能覆盖人工修改或已确认内容。
- 英语仅做材料和文案准备，不包含录音评测、官方分数预测或自动制作视频。
- 云端 DeepSeek API；统一使用项目方 API Key，仅由后端管理。
- 全部用户外部调用预算合计暂定 100 元/月，不含已有服务器费用；该数是预算目标而非费用预测。
- 腾讯云：4 核 CPU、4GB 内存、40GB 系统盘；已有宝塔 Linux 面板，发行版及现有服务占用未确认。
- 抖音官方申请和审核等待不计入工期；持续数据源未接通前，不宣称自动监控已经完成。
- 本计划的一人开发时间包括联调和必要验证；用户拍摄、剪辑、备考、实际发布的时间不包含在 15 小时中。

## 2. 开工准备与排期默认值

- W1-D1 检查并记录 Java、Maven、Node、Docker 可用性。安装环境占用同一天预算，超时进入机动时间。
- DeepSeek 凭据通过本地环境配置，用户不在聊天或文档中粘贴密钥。
- W1-D6 完成一个搜索 MCP 服务的选择与真实接入。无凭据时可用替身继续其他任务，但真实 MCP 接入仍是未完成项；第 4 周里程碑必须明确其状态。
- 第 1 周开始记录每次真实模型试跑的用量；自动化回归使用固定响应或模拟服务，仅在验证供应商接入时做少量真实调用。
- 第 1 周登记邮箱服务、飞书测试机器人、服务器访问、域名和 HTTPS 的准备状态，分别在第 6 周和第 8 周使用。等待外部开通可以与编码并行。
- 资料导入先支持 TXT、Markdown、粘贴文本及可提取文字的 PDF；单份默认上限建议 5MB，正文上限建议 10 万字符。首轮使用后调整。链接先保存来源和摘录，网页检索通过已配置的 MCP 服务完成。
- 小规模资料先做 MySQL 标题/正文关键词检索，以 10 条人工查询评估效果；不在本轮默认增加 Embedding 供应商和向量数据库。
- 初版默认一个付费后台生成任务并行，图流程最多 3 轮工具调用、结构化输出最多额外修正 1 次。W5 用实测时延和费用调整。
- 调度使用用户配置的周生成时间，默认时区 Asia/Shanghai；开发测试缩短周期后必须恢复。
- 数据复盘用导入模板验证；没有真实作品时可以标注为演示的样例测试功能，但运营效果验证仍待真实发布数据。
- 现有宝塔服务优先盘点后再安排入口及端口，不默认重装系统，也不默认同时启动两个 Nginx 或两套数据库。

## 5. 关键接口与状态约定

这些是排期采用的最小接口合同，便于前后端并行思考；实现时将其写入接口说明。用户身份统一来自登录态，请求体不得接收可覆盖当前身份的 userId。

| 任务组 | 接口与输入 | 输出或约束 |
| --- | --- | --- |
| W1/W2 身份 | POST `/api/auth/login`：email、password；POST `/api/auth/register`：email、password、inviteCode；POST `/api/auth/logout`；GET `/api/auth/me` | 服务端会话；登录失败不泄漏账号是否存在；浏览器 Cookie 与 CSRF 保护按 Spring Security 配置 |
| W2 账号 | GET/POST `/api/accounts`；GET/PATCH `/api/accounts/{accountId}` | 返回 id、name、positioning、audience、columns、weeklyTarget；归属不匹配返回 404 |
| W2 资料 | POST `/api/materials`；GET/DELETE `/api/materials/{materialId}`；GET `/api/materials/search?accountId=...&q=...` | 返回所属用户可见的 materialId、title、snippet、sourceUrl；关联账号也必须属于本人 |
| W3 生成 | POST `/api/generations`：accountId、conversationId、mode、instruction、requestId，可选 draftId、expectedVersion | mode 为 TOPICS / SCRIPT / WEEK_PLAN；返回 runId、status；GET `/api/generations/{runId}` 查询状态和结果 |
| W3 内容 | GET/PATCH `/api/drafts/{draftId}`；POST `/api/drafts/{draftId}/confirm` | 修改请求带 expectedVersion；响应包含新的 version；并发版本冲突返回 409 |
| W4 排期 | GET/POST `/api/plans`：accountId、weekStart；PATCH `/api/plans/{planId}/items/{itemId}` | 计划项包含栏目、日期、草稿引用、人工确认状态；已发布链接由用户手动填写 |
| W5 任务 | GET/POST `/api/tasks`；PATCH `/api/tasks/{taskId}`；GET `/api/tasks/{taskId}/runs` | taskType 为 WEEK_PLAN 或 OPERATION_REVIEW；weekStart + taskId 等稳定字段组成运行键；启停和时区属于本人配置 |
| W5 用量 | GET `/api/usage?month=YYYY-MM` | 仅展示本人用量和额度；系统总预算由服务端统一核验 |
| W6 通知 | GET/PUT `/api/notification-settings` | 渠道选择、邮箱与 Webhook 配置；读取时敏感字段脱敏，不能返回解密密钥 |
| W7 导入 | POST `/api/imports/metrics/preview`；POST `/api/imports/{importId}/confirm` | 返回逐行错误与统计；确认阶段再次校验归属和重复键 |
| W7 复盘 | GET `/api/analytics?accountId=...`；POST `/api/reviews`：accountId、from、to | 数值由后端计算；报告返回观测窗口、数据更新时间、来源和建议；任务仍使用统一运行记录 |

### 最小数据约定

- 选题：id、accountId、column、title、audience、angle、hook、outline、sourceIds、rationale。
- 脚本：id、topicId、spokenText、shootingNotes、sourceIds、status、version。英文材料的断句和表达解释属于正文的结构化段落。
- 草稿审阅状态：DRAFT / CONFIRMED。编辑确认稿需要显式操作并回到 DRAFT；发布记录是独立状态，避免把确认等同发布。
- 任务状态：PENDING / RUNNING / SUCCEEDED / FAILED / NEEDS_ATTENTION。NEEDS_ATTENTION 用于无法确定外部调用是否完成等情况，不能无条件自动重试。
- 通知状态：PENDING / SENT / FAILED / UNKNOWN。无法确认第三方是否接收时记 UNKNOWN，不承诺外部渠道严格只收到一次。
- 业务状态和任务恢复依据保存在 MySQL；Redis 或锁失效不能成为丢失归属信息、草稿或任务记录的理由。
- 缓存 key、对话 ID、后台执行上下文均绑定 userId；执行本地 Tool 前校验所属账号、资料或草稿。MCP 工具只接收必要查询参数。
- 首版内容页面对外部材料和模型生成文本采用安全渲染，不能把返回内容直接当作可执行 HTML。

### 作品指标模板

W7-D1 创建的 `docs/templates/video-metrics.csv` 至少包含：

```csv
accountId,videoId,capturedAt,views,likes,commentCount,source
```

capturedAt 使用带时区的时间，空字段表示未知，数值 0 表示观测为零。相同用户、账号、作品、采集时刻和来源构成相同快照；相同键不同数值必须提示冲突，不能静默累加。两个采集点的差值表示观测区间变化，不冒充抖音官方自然日增量。

评论模板至少包含：

```csv
accountId,videoId,commentId,text,capturedAt,source
```

模板不要求上传评论者手机号、账号令牌等无关个人信息。演示文件与真实导入分别标记；样例值不写入真实运营结论。

## 6. 各阶段怎样验证

### 本地构建与测试命令

在项目根目录执行。W1-D1 建立 Maven 工程及下面的前端 scripts 后，这些命令才可运行；计划编写阶段不运行尚不存在的应用。

前端 `frontend/package.json` 的 scripts 合同：

```json
{
  "scripts": {
    "dev": "vite",
    "typecheck": "vue-tsc --noEmit",
    "build": "vue-tsc --noEmit && vite build"
  }
}
```

安装依赖后提交 package-lock.json，后续使用 npm ci 复现。以下命令逐条执行，不必在每个小改动后重复所有检查：

```powershell
docker compose -f compose.dev.yml up -d
mvn -f backend/pom.xml test
npm --prefix frontend ci
npm --prefix frontend run typecheck
npm --prefix frontend run build
```

期望：开发依赖健康；Maven 输出 BUILD SUCCESS 且相关用例没有被意外跳过；前端类型检查与构建退出码为 0。数据库隔离、重复任务和导入幂等测试连接专用测试库，不能复用生产库。

只运行相关测试的示例：

```powershell
mvn -f backend/pom.xml "-Dtest=MaterialIsolationTest,DraftVersionTest" test
mvn -f backend/pom.xml "-Dtest=TaskRecoveryTest,BudgetReservationTest,NotificationDeliveryTest" test
mvn -f backend/pom.xml "-Dtest=MetricsImportTest,OperationReviewTest" test
```

测试替身与真实供应商的检查分开记录。真实接入检查须实际发生模型、Tool、MCP 调用；测试替身通过不能作为外部服务已接通的证明。

### 需要留下证据的具体场景

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 跨用户读取 | 用户甲创建账号及资料，用户乙请求其资源 ID | 404；列表、检索和模型工具均不返回甲的数据 |
| 并发编辑 | 两个页面读取草稿 version=1，依次提交两个修改 | 首次成功形成新版本，第二次 409；页面提示重新读取 |
| 重复周计划 | 同一用户、账号、周起始日以相同 requestId 连续提交 | 得到同一逻辑运行，不创建两份相同批次 |
| 部分失败 | 一条 Java 成功、另一条失败 | 状态清楚，已有成功草稿可保留；重试不覆盖已确认项 |
| 重启恢复 | 执行到资料检索完成后停止并重启服务 | 能查询持久运行记录；按已保存阶段安全恢复或标明需处理 |
| 配额竞争 | 剩余额度仅够一次调用时同时发起两个预留 | 最多一个通过；另一个明确拒绝或排队重新检查 |
| 通知独立 | 邮件服务拒绝，飞书正常 | 报告已保存，邮件失败可查询，飞书成功 |
| 指标口径 | 同一作品先 100 播放后 150 播放；另一作品播放缺失 | 观测变化为 50；缺失项保持未知，不能参与伪造的增长率 |
| 备份恢复 | 恢复到隔离测试库，读取指定用户、资料、计划、任务 | 记录和关联完整，生产数据保持原状 |

涉及 Cookie 的集成测试应使用带 Cookie 保存及 CSRF 处理的测试客户端，不能靠跳过安全过滤器让业务测试通过。

| 邮件 + 飞书 | W6-D1 至 D6 | 两渠道独立、凭据保护、带权限的站内链接 |
| 自有作品指标和评论 | W7-D1 至 D6 | 导入、去重、口径准确、有来源复盘 |
| 同行参考 | W2-D4、W7-D4 | 可用材料辅助选题，缺失指标不猜测 |
| 腾讯云和宝塔部署 | W8-D1 至 D4 | 共存、健康、HTTPS、外部服务实际可达 |
| 备份、恢复、运行文档 | W8-D5 至 D7 | 隔离恢复成功、实测资源和使用记录 |

- **里程碑①，W4-D7，累计 60 小时：** 从邀请注册到一周内容生成、修改、确认、排期可实际使用。关键隔离及来源问题未通过时，不进入“已完成”。
- **里程碑②，W6-D7，累计 90 小时：** 定时任务、用量、邮件及飞书完整联调；真实渠道未验证就保留未完成标记。
- **里程碑③，W8-D7，累计 120 小时：** 部署、恢复、数据导入与复盘流程通过。真实运营效果和抖音自动采集能力分别按实际数据来源验收。

## 8. 遇到延期怎样调整

| 情况 | 调整方法 |
| --- | --- |
| 第 1 周框架、模型或 MCP 接入超时 | 用周日机动时间处理；仍未解决则记录阻塞点、顺延依赖该接入的任务，其他前端/资料工作可继续 |
| 邮件、飞书、域名等外部配置未准备好 | 继续其余模块，使用测试替身做业务回归；真实接入保持未完成，不以模拟成功代替验收 |
| 第 4 周尚不能完成三条可用内容 | 优先修复资料、脚本、编辑和隔离问题，再重新估算自动化阶段；不通过删掉已确认功能缩小交付承诺 |
| 尚未发布作品或取得真实数据 | 用清楚标记的演示样例验证导入和计算；真实效果验收等待实际数据 |
| 抖音官方审核未通过 | 保留数据导入路径；将自动同步作为依赖权限的单独接入工作，不占用整个项目的等待时间 |
| 第 8 周仍有关键验收失败 | 启用第 9 周最多 15 小时缓冲，按数据安全/隔离、主链路、部署可用性的顺序修复；仍不通过则据实调整上线时间 |
