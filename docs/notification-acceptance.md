# 邮件与飞书真实收件验收

入口：本机服务启动后访问 `http://127.0.0.1:5173/#notifications-title`，登录后找到“通知设置”。2026-10-23 已使用工作台保存的真实配置各发送一条邮件、飞书通知，两者发送端均为 `SENT`；用户已确认两边收到且链接能打开对应草稿，W6-D2 / D3 验收完成，见[本轮验收记录](qa/2026-10-23-w6-live-notifications.md)。下面保留配置说明，固定状态见 [开发进度](PROGRESS.md)。

## 填写工作台

| 渠道 | 页面字段 | 填写说明 |
| --- | --- | --- |
| 邮件 | 收件邮箱 | 你指定用来接收测试通知的邮箱 |
| 邮件 | 发件邮箱、SMTP 用户名 | 按发信服务的配置填写；SMTP 用户名不一定等于邮箱 |
| 邮件 | SMTP 服务器、端口 | 使用服务商提供的 STARTTLS 主机和端口；页面默认 587，需以服务商配置为准 |
| 邮件 | SMTP 密码 | 在工作台填写 SMTP 密码或服务商授权码，不要发到聊天或保存进仓库 |
| 飞书 | 机器人 Webhook | 指定测试群中自定义机器人的地址，格式为 `https://open.feishu.cn/open-apis/bot/v2/hook/…` |
| 飞书 | 签名密钥 | 与该机器人对应的签名密钥，只填工作台 |

当前邮件发送代码要求 STARTTLS，不支持仅填写隐式 TLS 端口就切换协议。飞书当前要求 Webhook 和签名密钥同时具备。

启用“邮件”和“飞书”，点击“保存通知设置”。成功后新凭据输入清空，只显示已配置提示；再次保存时留空保留已保存密文。刷新投递状态不会丢弃未保存的输入。

## 配置后提供的信息

回复登录工作台的邮箱、测试收件邮箱和飞书测试群名称即可，不提供密码、授权码、Webhook 或签名密钥。登录邮箱用于确定设置所属用户；群名称用于确认人工收件目标，不是机器人接口参数。

用户已选择两渠道均验收。目标明确、配置就绪后，发送一轮指定测试通知并分别核对收件、投递状态和草稿链接。`SENT` 是发送端记录，还需要人工确认邮箱和群内实际收到；`UNKNOWN` 表示结果不明，不能直接重发。渠道失败和生成失败分开记录，不把本地替身测试当作真实送达。

启用渠道后，成功周任务会创建通知。后台也会恢复已有 `PENDING` 和到期 `RETRY`；暂停渠道不删除旧待投递记录，重新启用后仍可能发送。验收期间先核对队列，不为测试开启长期自动生成扫描。当前本机链接指向 `127.0.0.1`，需在运行工作台的电脑上打开；云端网址及 HTTPS 属于部署验收。
