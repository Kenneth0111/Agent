# 自动生成与通知运行手册

当前本机里程碑②已通过[真实定时演练](qa/2026-10-23-w6-wallclock-acceptance.md)。开发环境恢复为生成 / 复盘扫描关闭、现有周生成任务关闭；邮件与飞书配置按用户设置保留。通知链接当前仅供运行工作台的电脑访问，云端入口尚未部署。

## 配置与运行

1. 在工作台账号配置中核对栏目。当前整周生成固定为“Java 面试 / Java 面试 / 英语跟读”，每周目标设为 3，账号栏目使用“Java 面试 / 英语跟读”；自定义显示名称不会自动映射，旧空排期也不会随账号修改自动更新。
2. 在“运行与用量”选择账号，保存星期、时间、时区、生成要求和每条稿件的 1 至 3 份资料；资料需属于当前用户，英语材料按实际内容和用途选择。先保持任务关闭。
3. 按[通知说明](notification-acceptance.md)保存并启用需要的渠道。核对旧待投递记录，启用渠道可能恢复该渠道此前的 PENDING / 到期 RETRY。
4. 长期运行前配置用量单价与预算，核对服务地址及通知回链。后端环境变量 `GENERATION_JOBS_SCHEDULER_ENABLED=true` 开启生成扫描，需要重启对应后端进程；任务本身也要在页面启用，两者缺一不可。`REVIEW_JOBS_SCHEDULER_ENABLED` 独立控制复盘，本步骤不需要开启它。
5. 后台约每分钟检查一次，按任务时区在所选星期、所选时间之后触发；执行时刻不保证精确到秒。错过整个所选星期不会在次日补跑。同一任务以当地周一日期作为周期键，一周只预约一次自动运行。
6. 在“运行与用量”刷新结果，区分 `SCHEDULED` 和 `MANUAL`。成功保存三条草稿后分别投递通知；收到通知后登录回站查看，再到周计划选择空白周次、匹配栏目、关联批次、修改保存并确认。确认不表示自动发布抖音。

修改同一周的任务时间不会绕过已有周期键。“手动运行”是额外生成，仍会调用模型，不能用它判断本周自动任务是否正常去重。整周草稿每次通常涉及六个模型阶段，验证重试时应先查看已有任务和用量。

## 暂停、异常与恢复

| 情况 | 操作与边界 |
| --- | --- |
| 暂停自动生成 | 关闭该账号任务；要暂停所有周生成扫描，再关闭后端扫描开关并重启。暂停不撤销已经开始的模型调用，也不禁止手动运行。 |
| 模型 / 资料失败 | 先查运行错误和失败节点，成功通知不应被创建；已有草稿、阶段与账本保留。不要通过删除周期记录或反复点手动运行来处理未知付费结果。 |
| 配额 / 预算拒绝 | 在用量区域核对暂停原因、统计周期和待核对费用，确认实际账单与配置后再调整；不凭通知发送失败修改预算。 |
| 一个渠道失败 | 草稿与另一渠道独立保存。检查该渠道的配置和独立投递记录，不重新生成整周内容来测试发送。 |
| 飞书 RETRY | 仅明确限流自动重试，最多三次发送尝试，退避 1 / 5 分钟；暂停渠道会阻止下一次领取。 |
| UNKNOWN | 发送结果不明，先人工核对收件，系统不自动重发；不要直接重置为 PENDING。 |
| 进程中断 | 已入队 PENDING 和到期 RETRY 可由通知扫描器恢复；中断的 SENDING 超时后为 UNKNOWN。生成中断按已保存阶段恢复或保留人工核对状态，不保证所有未知调用可重放。 |
| 通知已发送但看不到草稿 | 用任务所属账号登录；他人链接返回 404，匿名为 401。核对通知地址是否仍为本机回环地址，以及对应整周批次是否存在。 |

通知扫描独立于生成 / 复盘开关，每约 60 秒运行。只关闭生成扫描不能保证不发送已有通知；启用测试副本前应先按[备份恢复手册](backup-recovery.md)关闭副本通知渠道，避免向真实收件人重复发送。

一次验收结束后恢复原任务的星期、时间、时区、启停状态、生成要求与资料选择，停止临时测试后端，核对无新增周期、无待投递且用量不再增加。本轮恢复证据见[里程碑②记录](qa/2026-10-23-w6-wallclock-acceptance.md)。
